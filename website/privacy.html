Privacy Policy

Effective date: August 7, 2026 · Product: Phil (Chrome extension)

Phil is a private on-device browser AI chief of staff. This policy explains what stays on your device, what may leave your device when you opt in, and how we handle optional telemetry.

Summary

  • By default, chat, page text, prompts, goals, focus data, reminders, Persistent Project knowledge, and memories stay on your device. Phil does not send them to Phil servers for inference.
  • Analytics and crash reporting are off by default and only run if you explicitly opt in from Privacy / Settings.
  • Optional features (Google web research, Gmail, Calendar, browser history) may send data to third parties you already use — only when enabled.

What stays on your device

Unless you enable an optional egress feature, the following remain local:

  • Agent and chat prompts, replies, and conversation history
  • Current-page extracts and selection text used for summarize / explain
  • Goals, reminders, focus / dwell summaries, and Persistent Projects
  • Memories and conversation search indexes stored in IndexedDB / Chrome storage
  • Calendar event summaries after sync, when Calendar is enabled (stored locally for planning)
  • Downloaded AI model weights cached for offline reuse (Cache API)

What may leave your device

Model download (CDN)

The first time you download an AI model (and when updating model artifacts), Phil fetches weights and runtime assets from model hosting CDNs such as Hugging Face / related mirrors listed in the extension host permissions. After download, inference runs on-device via WebGPU / WebLLM. No Phil cloud inference endpoint is used.

Google web research (optional / when used)

When you ask Phil to research the web, Phil uses Google as the default search engine (SERP via browser tabs). Search queries and page loads go to Google under Google’s terms. Phil does not operate a separate research proxy.

Gmail (optional)

If you connect Gmail (OAuth API mode or session mode while signed into mail.google.com), Phil may read message metadata/bodies needed for list/read/draft flows and may send mail only after you confirm. OAuth tokens stay on-device; Phil does not operate a mail server.

Google Calendar (optional)

Calendar is a first-class, skippable onboarding step. When connected, Phil may sync today’s events (and related calendar reads for planning) through Google Calendar / Google APIs. Event data used for planning is cached locally. When skipped, Phil plans without calendar events and can prompt you to enable Calendar later in Privacy.

Browser history (when enabled)

If you grant the optional History permission for browser memory, Phil may index visit titles/URLs locally so you can ask things like “find that article from last week.” History data is not uploaded to Phil servers. Clearing or disabling browser memory removes indexed hits.

Permissions inventory

Required and optional Chrome permissions are documented in PERMISSIONS.md in the product repository and mirrored in the in-extension Privacy dashboard (local vs leaves-device sections). That dashboard is the live inventory of what is granted on your profile.

Analytics and crash reporting

Analytics default OFF. Crash reporting default OFF. Fresh installs do not emit analytics or crash reports. If you later opt in from Privacy / Settings, the UI will state at a high level what is collected. You can turn these off again at any time.

Data you can clear

From Privacy controls you can clear chats, memories, focus history, and (when applicable) browser memory indexes. Revoking optional permissions (Gmail, Calendar, history) updates the dashboard and disables the related features until re-enabled.

Children

Phil is not directed at children under 13, and we do not knowingly collect personal information from children.

Changes

We may update this policy as the product evolves. Material changes will be reflected on this page with an updated effective date. Continued use after changes constitutes acceptance of the updated policy.
